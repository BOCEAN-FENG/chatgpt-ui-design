# 验收规则

## 执行矩阵

先运行现有项目要求的构建／类型检查，再用可用的浏览器或原生应用运行工具查看界面。使用真实运行结果，不能拿设计稿截图冒充程序截图。至少覆盖：

| 平台／状态 | 最低检查 |
| --- | --- |
| Web 基线 | `1440×900`，浅色和深色，主要页面 |
| 中等窗口 | `1024×768`，侧栏与内容均可用，不强挤三列 |
| 窄屏 | `390×844`；有移动端支持时补 `360px`，抽屉与关闭操作 |
| 桌面应用 | 真实桌面启动、最小窗口、放大字体／DPI、自定义标题栏操作（如存在） |
| 核心流程 | 至少一个完整任务，及相关 loading／error／empty 状态 |
| 复杂文本 | 长中文、长文件名、链接或代码；光标和焦点可见 |

对现有项目按目标用户的实际窗口调整测试矩阵。设计新主题后用 `scripts/check_tokens.py` 验证本包 token；集成到工程后另检查实际渲染结果，不以本包脚本代替产品验收。

## 必须修复的阻断项

- 必要按钮没结果、错误成功提示、无法关闭的浮层、输入法回车误发送。
- 文字或操作被遮挡，主内容意外横向溢出，末条消息被 composer 压住。
- 深色主题存在白底孤岛、不可读文字、消失图标或原生弹窗严重不协调。
- 页面与业务不匹配：把设置做成聊天页、将表格拆成无用大卡片、把实用软件做成营销首页。
- 键盘不可达、焦点不可见、图片／图标缺少必要名称、按钮命中区过小。
- 缺字、乱码、字体未加载、意外使用 serif 回退或混用 emoji 作为系统图标。

## 截图评审

以 100% 视图检查，同时放大关键控件。截图能力允许时先做整屏，再查看输入区、侧栏和浮层局部。逐项记录通过或问题：

1. **整体：** 大面积中性画布，主要任务一眼可见，无无关装饰。
2. **几何：** 左右对齐一致，间距服从阶梯，圆角有层级，没有随机尺寸。
3. **文字：** 结构与正文层级清楚，辅助信息可读，中文与英文基线协调。
4. **控件：** 同种按钮一致，图标同一笔画与尺寸，选中与 hover 可区分。
5. **内容：** 文案符合真实产品；没有设计说明、假统计、无用途的色块和装饰图标。
6. **状态：** 浅深色、抽屉／菜单、焦点、禁用和错误仍然成立。

若有用户参考截图，在相同内容类型、主题、窗口尺寸下比较。关注侧栏比例、内容宽度、文字密度、控件外形与层次，不能以“都有灰色背景”判定相似。数值像素差受字体、系统与内容影响，不拿像素比对单独判定审美质量。

允许一次针对明显问题的修正后重新截图；有新问题继续修正。实际无法运行原生桌面时，分别报告已通过的资源／代码校验与未做的原生视觉检查，不声称全部平台已实测。
