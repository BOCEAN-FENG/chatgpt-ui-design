# 视觉系统

## 色彩角色

以 `assets/tokens.css` 为数值真源。以下角色面向独立产品，属于参考 ChatGPT 的工程基线，不代表所有版本的官方内部值。改变颜色时同时更新两种主题并运行对比度检查。

| 角色 | 浅色基线 | 深色基线 | 用途 |
| --- | --- | --- | --- |
| `canvas` | `#ffffff` | `#212121` | 主画布 |
| `sidebar` | `#f9f9f9` | `#181818` | 导航侧栏 |
| `surface` | `#f3f3f3` | `#303030` | 用户消息、分组、输入区域 |
| `overlay` | `#ffffff` | `#2a2a2a` | 菜单、对话框 |
| `hover` / `pressed` | `#ececec` / `#e3e3e3` | `#383838` / `#454545` | 交互反馈 |
| `text` | `#0d0d0d` | `#f4f4f4` | 主要文字 |
| `secondary` | `#5d5d5d` | `#cdcdcd` | 图标、次要文字 |
| `muted` | `#666666` | `#b2b2b2` | 提示、时间、占位文字 |
| `border` | `#e2e2e2` | `#484848` | 装饰分隔，不能作为控件唯一识别线索 |
| `border-strong` | `#858585` | `#909090` | 需要可辨边界的输入和控件 |
| `action` / `on-action` | `#171717` / `#ffffff` | `#f4f4f4` / `#171717` | 主操作、发送 |
| `focus` | `#2563eb` | `#93c5fd` | 键盘焦点，仅在需要时显示 |

把成功、警告、失败颜色留给实际状态。搭配图标或文字，避免仅靠红绿区分。品牌强调色默认不启用；用户指定时只用于少量有意义的位置，并补查对比度。不要把“AI 风格”理解为全站紫色，也不要把旧版品牌绿色机械地涂到全部操作上。

## 字体与文字

- 使用系统无衬线字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "Noto Sans", "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`。已有合法随包字体时可沿用；不要依赖联网字体才能正常显示。
- 在 Windows 上检查 Segoe UI 与微软雅黑的实际回退；在 macOS 上检查系统字体与苹方。官方品牌字体的名称不等于产品所有平台的 UI 字体，不能仅凭品牌页面就把网页全站换成该字体。
- 结构文字用 `14/20px`，辅助文字用 `13/18px`，主内容用 `16/26px`，页标题用 `24/32px`。聊天空白页标题可用 `28–32px`，一般软件页面不套用营销展示字号。
- 常规字重 `400`，控件／小标题 `500`，重点及页标题 `600`。不要到处加粗，不要给汉字全局加负字距或 `uppercase`。
- 中文正文行高取 `1.6–1.75`；结构控件取 `1.4–1.5`。长中文不强行限定为单行，导航标题可省略但应可查看完整名称。
- 数字列、时长、版本号视需要使用等宽数字；仅代码和终端使用等宽字体。代码块独立横向滚动，正文正常换行。
- 给文字容器设真实宽度与 `min-width: 0`，长路径、链接和混合中英文采用合适的换行规则。不要用缩小字体解决布局问题。

## 间距、圆角、边界

采用 `4, 8, 12, 16, 20, 24, 32, 40, 48, 64px` 的间距阶梯。基准：侧栏内边距 `12px`，菜单项横向 `12px`，页面边距 `24px`，正文段间 `16px`，大区块间 `24–32px`。窄屏页面边距 `16px`。

| 部件 | 圆角 | 基准尺寸 |
| --- | --- | --- |
| 导航项、普通按钮 | `8–10px` | 高 `36–40px` |
| 输入框、选择器 | `10px` | 高至少 `40px` |
| 菜单、轻量分组 | `12–16px` | 内边距 `6–16px` |
| 文件卡、对话框 | `16px` | 由内容决定，不做夸张大圆角 |
| 消息气泡、消息输入容器 | `24px` | 输入容器可随内容增高 |
| 圆形图标按钮 | `999px` | 桌面至少 `36px`，触屏至少 `44px` |

优先通过背景、间距和文字层级分组。仅在真正分组或分层的位置画边界；普通段落、每行文字和助手回复不套卡片。默认常规面板无阴影，浮层才使用柔和阴影；输入容器可有极轻阴影。不要为“精致”增加多重边框、亮边和纹理。

## 图标与标识

- 复用项目已有的单一图标库；新工程可选 Lucide、Heroicons 等一套线性库。统一 `24×24` 设计网格，显示 `18–20px`，线宽约 `1.7–2`，圆端点与圆转角。
- 没有图标库时使用 `assets/icons.svg` 的自绘基础符号。用 `<svg class="cg-icon" aria-hidden="true"><use href="icons.svg#search"/></svg>`；单文件场景内联所需 symbol，避免 `file://` 对外部 SVG 引用的限制。
- 工具图标采用 `currentColor`。黑白反转时继承按钮前景；禁用时用专用禁用色。不要给每种功能分配一个随机颜色。
- 将菜单／收起侧栏、新建、搜索、文件夹、附件、发送、停止、复制、重试、更多、设置等动作映射到稳定图形。同一个动作跨页保持同一图形。
- 区分产品 Logo、品牌标志、头像、工具图标和文件类型图标。优先使用用户产品现有 Logo；没有时先用产品名或简单单色字母标识，不制造一个像 OpenAI 结形标志的默认 Logo。
- 保持产品自己的身份。只有在用户明确需要展示 ChatGPT／OpenAI 本身时才使用对应的正式品牌资产，并保留其比例、留白和用途；样式相似不要求改产品名称或替换其 Logo。
- Logo 在侧栏头部约 `24–28px`，头像约 `28–32px`；文件图标约 `20–24px`。保证浅深色版本可辨，缺图有稳定回退。

## 明确的设计判断

用一个占据注意力的主要动作引导一个局部任务。可以在独立区域分别有主操作，不机械限制整页只能有一个按钮。让帮助文字解释用户需要做的决定，不解释 CSS、组件名或布局技术。

示例反例：将“新建任务”做成黑色按钮，其他操作用文字或轻边框；让 20 个任务形成一张列表，而非 20 个带阴影的大卡片；将助手回复直接排版在画布上，而不是仿即时通信软件给双方都加同样的彩色气泡。
