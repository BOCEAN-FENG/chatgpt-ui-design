# 组件规范

## 骨架与导航

| 组件 | 实现要求 |
| --- | --- |
| 侧栏 | 默认宽 `260px`，宽度可在 `240–280px` 适配；独立滚动的中段，底部账户／设置固定在侧栏布局底部，不能压住列表 |
| 侧栏项目 | 高约 `36px`，小圆角，图标和标题左对齐；hover 浅灰，selected 有稳定背景与 `aria-current`，不是只在 hover 时显示当前页 |
| 标题栏／页头 | 网页默认高 `56px`；左放页面或工作区名，右放当前上下文的操作。不要额外叠一个装饰性品牌横幅 |
| 搜索 | 图标、可读输入、必要的清除；无结果给出简短可执行提示；查找不伪装成不可编辑的按钮 |
| Tabs | 用于同一对象的不同视图，使用轻下划线或单一选中底色；不要为路由导航和模式选择混造三层 Tabs |
| Segmented control | 用于互斥模式，如浅色／深色／系统；浅灰底、选中项清楚、键盘可操作 |
| 更多菜单 | 收纳次要命令；打开后贴近触发器，超出边缘自动翻转；点击外部和 Escape 关闭，焦点返回触发器 |

## 按钮与输入

| 类别 | 形态 | 状态及约束 |
| --- | --- | --- |
| Primary | 黑底白字，深色反转；高 `40px`，横向 `14–16px` | hover／pressed 对比清晰；加载保持宽度，禁用真正阻止操作 |
| Secondary | 透明或画布底，轻边框，正常前景 | 用于取消、导出等次要命令，不把所有按钮都做成黑色 |
| Ghost | 无底无边，hover 才显中性背景 | 工具栏、侧栏和次要行操作；必要操作不能仅 hover 可见 |
| Icon-only | `18–20px` 图标，桌面命中区 `36–40px` | 有可访问名称，指针与键盘均可得 tooltip；触屏 `44px` |
| Send / Stop | 圆形实心反转底，向上箭头／实心方块 | 无内容时发送禁用；生成时明确切换停止功能和名称 |
| Destructive | 默认文字＋明确动词，使用 danger 语义色 | 不将删除作为一般主操作；有确认／撤销时沿用真实产品策略 |
| Text input | 持续可见标签、`40px` 高、`10px` 圆角 | 默认／hover／focus／error／disabled；错误有具体文字，不只红框 |
| Select | 真实选择控件或成熟可访问组件，尾部统一 chevron | 当前值可读；长选项不会顶开布局；键盘可开关与选择 |
| Toggle | 用于立即生效的二元偏好，checked 可黑白反转 | 有标签和清晰状态；需要提交的表单选择用 checkbox 更合适 |

默认按钮不设置全局 `transition: all`，不通过缩放按钮制造跳动。focus ring 不挤动布局。保留文本、tooltip 和可访问名称的一致性。

## 对话组件

1. 让对话与 composer 共用 `760px` 的基准最大宽度，可在 `720–800px` 微调；用户消息右对齐并使用浅灰圆角背景，宽不超过内容列的约 `80%`。
2. 将助手文字直接放在画布上；使用舒适行高及自然段，不默认增加大头像、彩色气泡、粗外框或整块卡片。给代码、文件等独立内容适当分组。
3. 让 composer 具有柔和中性背景、约 `24px` 圆角、`12–16px` 内边距。文本与工具栏分层，附件入口在左，发送／停止在右；输入 `1–8` 行后内部滚动。
4. 将 composer 放在独立布局行，不用覆盖正文的任意 `position: fixed`。正文滚动区具备 `min-height: 0`，底部内容可完整看见。窄屏留出安全区与软键盘空间。
5. 空白页可将一句短问候与 composer 成组置于画布偏上的中心；最多给少量有用途的建议入口，不添加营销副标题与介绍卡片。已有消息时回到正常正文与底部输入布局。
6. 用附件条目展示真实文件名、类型、移除与上传状态。发送失败保留草稿和附件；流式回复支持停止、部分结果和重试。输入法组合期间禁止 Enter 误发送。
7. 助手操作栏以轻量复制／重试等图标呈现；触屏与键盘可达。仅在内容真正复制后显示成功反馈；失败显示可行动的结果。

## 列表、表单与设置

- 列表使用清楚的行、列和轻分隔，行高约 `48–56px`。标题、次要信息、状态、行操作有固定对齐关系。状态用小字或弱色 badge，不抢占整行。
- 表格保持原生表格语义；数值列右对齐，必要时横向滚动在表格容器内发生。稠密数据保持可读，不把数据强拆成聊天消息。
- 设置采用分类导航和内容区，设置行左标签／说明、右控件，相关行之间轻分隔；页面表单宽约 `640–800px`，标签、帮助文字、校验状态始终对应。
- 设置弹窗在桌面可为 `640–760px`；在窄屏改全宽或全屏面板，允许内容滚动且保留关闭入口。原生设置窗口服从操作系统窗口行为。
- 文件／结果卡片仅用于可操作对象；给出名称、必要元数据和真实打开／下载动作。不要把一般文字包成文件卡片。
- 图表延续中性底色和少量语义色，图例、坐标和读数必须可辨；不要给图表增加发光、立体透视或渐变装饰。

## 浮层与反馈

Dialog 有标题、明确关闭方式、初始焦点、焦点约束和关闭后焦点恢复；长内容在面板内部滚动。菜单和 tooltip 只承担短内容。Toast 用于短暂反馈，表单错误与执行失败保留在相关位置，不让用户依赖一个很快消失的提示恢复任务。

加载时保留现有内容并局部反馈；只有确有等待且布局已知才用 skeleton。空状态解释当前缺少的内容并给下一步；错误区分网络、权限、执行失败，提供适用的重试或修正入口。
