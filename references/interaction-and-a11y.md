# 交互与可访问性

## 交互状态

实现默认、hover、pressed、selected、focus-visible、disabled、loading、empty 和 error 中业务涉及的状态。不要用 hover 替代 selected。按钮加载时锁住重复提交并保留可访问名称；请求失败保留输入和可恢复的上下文。

实现主题的浅色／深色／系统三种偏好；将选择存储在产品现有偏好体系。系统模式跟随系统变更，手动模式不被系统变更覆盖。Web 尽早设置根主题避免闪屏，组件和浮层读取同一语义色，不简单用 `filter: invert()` 反色。

对常规反馈采用约 `120–180ms` 的颜色或透明度过渡；抽屉可约 `180–220ms`。尊重 `prefers-reduced-motion`；不要把流式输出做成不断弹跳的布局或过度打字机动画。

## 键盘与输入法

- 用语义化 button、input、textarea、select；保持可预测 Tab 顺序和清晰焦点。必要图标按钮有名称，非文字 SVG 标记 decorative。
- Web 对话默认 Enter 发送、Shift+Enter 换行；`event.isComposing` 或组合输入尚未结束时不发送。尊重已有用户快捷键偏好和平台差异；普通多行表单不要自动套聊天的 Enter 发送。
- Cmd／Ctrl 快捷键按系统显示、实现和冲突检查；只注册需要的组合，不劫持浏览器的地址栏、刷新和常用系统快捷键。
- Dialog／抽屉打开时移入焦点，约束焦点、屏蔽背景交互，Escape 关闭，关闭后返回触发器。优先成熟组件或原生 `<dialog>`；不能只加 `aria-modal` 却仍让焦点跑进背景。
- Tooltip 对 hover 和 focus 都可见。菜单实现方向键、Home／End 和 Escape；做不到时优先简单原生控件，不能只贴上 `role="menu"`。

## 滚动与实时输出

让用户接近底部时自动跟随新消息；用户向上阅读时保持位置并提供“回到最新”。不要每个 token 都强制 `scrollIntoView()`。更新文件卡、状态或高度后复查布局，避免输入框覆盖最后一行。长输出可中止；中止后保留已生成内容并正确恢复发送状态。

局部更新正在生成的内容，不随每个片段重建整个页面、侧栏或既有操作按钮，防止丢失键盘焦点、选择区域和滚动位置。窄屏列表先给标题足够宽度，再把状态与行操作移到下一行，不将长中文挤成细碎窄列。

Web 对 streaming 状态提供简短的 `role="status"`，不要将整段高速变化的正文作为高频 assertive live region。原生框架使用对应可访问通知。

## 触屏与窗口

在窄屏及 coarse pointer 场景确保主要命中区至少 `44×44px`；不依赖 hover 才出现关键操作。保留可滚动内容、关闭入口和底部安全区；用实际软键盘状态核对 composer 可见性。不要通过全页 `overflow: hidden` 掩盖内容溢出。

## 可读性检查

普通文字目标对比度至少 `4.5:1`；大文字至少 `3:1`。焦点、必要控件识别及状态指示需与相邻背景达到适用的 `3:1`。装饰分隔线可弱于必要控件边界，不能把弱分隔线当唯一边界。禁用态也应足够看清其用途。

支持文字放大、系统字体缩放、键盘和读屏可访问名称；图片有与用途匹配的替代文字。错误信息与字段关联，状态不只靠颜色表达。对长中文标题、长文件名、连续 URL、中英混排及多行按钮文案做真实检查。
